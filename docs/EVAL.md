# Evaluation (proof of concept)

Generated by `npm run eval`. Public vendor docs, a **fictional** customer, and **synthetic** data that I designed, with problems planted on purpose. These numbers show the checks work on the cases I thought of. They are not a benchmark of real-world accuracy.

## 1. Verifier: planted errors in the model draft

Baseline: the saved model draft (claude-opus-5-5, 2026-11-05) has 70 cited facts. 69/70 verify (0 with a corrected line number), and 1 of 31 rows are held back:
- `custom_sheet/Snyk/versioning`: "Sunset" was labelled as an API version, but an API version must be a date such as 2024-10-15 (or the format YYYY-MM-DD). The source was mislabelled, so the item is held back. Draft text: "Each request sends a `version` query parameter as a date in `YYYY-MM-DD` format. Snyk recommends `2024-10-15`. Deprecated endpoints return a `Sunset` header with the end-of-support date."

This hold was not planted. Here the content was right, but the model tagged a header name as a version, so the citation was malformed and the verifier held the row back. Being strict costs one Confirm here, and it never shows a malformed fact.


Each planted error is added to that draft on its own and the plan is rebuilt. To count as caught, the planted fact itself must fail verification (or the planted token must be named in the hold reason), the row must be held back (shown as Confirm), and the bad value must appear nowhere in the output.

**18/18 planted errors caught.**

## 3. Duplicate detection on synthetic data

53 asset records from 3 tools, which are 27 real machines in the truth file.

| Measure | Value |
|---|---|
| Same-machine record pairs in the truth file | 36 |
| Pairs merged automatically | 33 |
| Correct automatic merges | 33 |
| **Wrong automatic merges** | **0** |
| Same-machine pairs not merged | 3 (all 3 sent to the review queue) |
| Review queue items | 4 (2 truly the same machine, 2 truly different) |

The design choice: weak evidence (same hostname only, shared IP only, a device name equal to a hostname) never merges on its own. It goes to a person. That trades some manual review for zero silent wrong merges, which matters because a wrong merge hides a machine from the risk figure.

Data checks on this data set: counts: block, review_queue: block, orphans: block, stale: warn, edr_coverage: warn. Ready to feed a risk number: no.
